# SolarTelligence SEO implementation audit

Research and implementation date: September 22, 2026. Target market: English-speaking Arizona homeowners, United States. Production release date: **not released**. This is a local implementation, not a claim of indexing, rankings, traffic growth, or conversion lift.

## 1. Business and evidence

Confirmed from `README.md`, `src/lib/brand.ts`, product components, privacy/terms pages, and read-only live requests:

- Public website: https://solartelligence.com. The brand constant spells the product `Solartelligence`.
- Free preliminary residential roof analysis, sunlight information, a data-dependent 3D panel layout, equipment/financing scenarios, and an emailed solar report.
- The address workflow is Arizona-only. The report is not an engineering plan, installation contract, lender approval, or guaranteed savings.
- Homeowner report delivery does not require installer follow-up. Sharing for installer contact is a separate opt-in.
- Next.js App Router, installed Next 16.3.5, React 19, TypeScript, Tailwind; Vercel hosting configuration; Google Maps/Solar, Supabase and Resend integrations.
- The homepage and legal pages already contain useful initial HTML despite interactive client components. No framework migration or SSR rewrite was warranted. The new guide is statically rendered.
- Roof/report UI is dynamically loaded. Authenticated dashboards and signed report access already exist and were preserved.

Business assumptions requiring confirmation:

- Qualified emailed-report requests, followed by explicit installer-contact requests, are the most useful conversion goals. This follows the implemented funnel, not an owner-provided revenue report.
- Lead/referral generation appears to be the commercial model. No verified commission arrangement, paying partner list, revenue per lead, installer credential, physical office, or business-history claims were available. None were invented or added.

Data/access limitations:

- Semrush returned `no_api_units`; no search-volume, difficulty, ranking, backlink or traffic estimates were obtained. No units or services were purchased.
- No authenticated Search Console or GA reporting data was used. Existing high-traffic pages cannot be identified from analytics. All existing public URLs were preserved.
- No GA4 loader was observed in the inspected live HTML. Local production builds explicitly report an unset `NEXT_PUBLIC_GA_MEASUREMENT_ID`. This does not prove that no other tracking exists or that Search Console is unverified; DNS verification is not visible in this repository.
- Search research below is a qualitative web-search sample, not a location-controlled rank-tracking study. Competitor forms were inspected from public page content; no competitor lead was submitted.

## 5. Verification and measurements

### Comparable laboratory results

Three cold-browser samples per route and viewport, median shown. Same installed Chromium 153.0.8010.12, warm local production server, 4x CPU slowdown, 80ms configured network latency, 1.6Mbps download / 750Kbps upload, external requests blocked, and an 8-second observation after DOMContentLoaded. No browser tests ran concurrently with the after benchmark. Viewports: 393 x 852 and 1440 x 900. These are browser-emulation lab results, not physical iPhone or real-user measurements.

| Page / viewport | LCP before -> after | FCP before -> after | Encoded response-body bytes before -> after | Auto video requests before -> after | CLS |
| --- | --- | --- | --- | --- | --- |
| Home / 393px | 1,800 -> 1,792 ms | 1,016 -> 1,004 ms | 1,231,235 -> 320,267 (**74.0% less**) | 3 -> 0 | 0 -> 0 |
| Home / 1440px | 1,864 -> 1,868 ms | 1,028 -> 1,032 ms | 982,235 -> 987,111 | 3 -> 3 | 0 -> 0 |
| Privacy / 393px | 944 -> 960 ms | 944 -> 960 ms | 223,688 -> 223,954 | 0 -> 0 | 0 -> 0 |
| Privacy / 1440px | 964 -> 960 ms | 964 -> 960 ms | 223,688 -> 223,954 | 0 -> 0 | 0 -> 0 |

Interpretation: the demonstrated improvement is mobile transfer avoidance, not a meaningful LCP improvement. Millisecond-level paint differences are within run variation; the privacy mobile result is slightly slower, not an improvement. Desktop motion is deliberately preserved. Requests include media range requests, not three unique videos. Transfer counts exclude headers and are limited to the observation window; the decorative video file itself is 3,837,519 bytes. Do not label these counts as a Lighthouse score or complete lifetime page weight.

Homepage loaded Next-script encoded bytes changed from 169,549 to 169,878 (+329); privacy stayed at 139,947. No JavaScript reduction is claimed. Local server TTFB medians were 1-2ms and are not evidence about production/CDN latency. All 24 comparable samples had no page errors and no horizontal overflow. LCP/CLS were observed without interaction; INP was not measured.

The new guide has no pre-change counterpart. Under the same lab conditions its three-sample median LCP/FCP was 964ms at 393px and 976ms at 1440px; 256,850 encoded response-body bytes, zero video requests, zero CLS, no horizontal overflow and no page errors at both sizes. Evidence: `qa-evidence/seo-guide/performance.json`. Its Next-script transfer includes the calculator destination prefetched by visible links; static rendering does not imply zero browser JavaScript.

Raw after evidence: `qa-evidence/seo-after/inventory.json` and `performance.json`. Screenshots: `home-393.png`, `home-1440.png`, `privacy-393.png`, `privacy-1440.png`, `guide-393.png`, `guide-1440.png` in that directory. Before counterparts are in `qa-evidence/seo-before`. ## 6. Remaining risks and approval needs

- **Production release is not authorized by this task.** Changes are local. Existing unrelated QA/video work was already dirty and has been preserved. Do not deploy or revert the entire working tree as an SEO-only release without reviewing the mixed changes.
- Obtain Search Console read-only access/export and the owner's GA4 property/measurement configuration. Do not create a duplicate property or insert an invented measurement ID.
- Before enabling GA4, prevent automatic collection of address-bearing `/estimate` query strings, signed report tokens, report IDs and private dashboard paths. Existing custom-event parameter filtering alone does not sanitize the default page URL or enhanced-measurement history tracking. Review consent/privacy configuration and test payloads without sending personal data.
- Correct `NEXT_PUBLIC_SITE_URL` to the canonical root during an approved configuration release. SEO URLs no longer depend on it, but report/PDF link builders still do. Their `new URL` behavior differs from Next metadata composition, so verify generated links separately rather than assuming every link has the same broken path.
- Review the temporary www redirect in Vercel and use a permanent redirect if this canonical host is the owner's long-term choice. No hosting change was made.
- No field Core Web Vitals, Search Console indexing confirmation, Rich Results Test service result, actual report-email delivery, live lead conversion or installer fulfillment is claimed. JSON-LD syntax, required breadcrumb fields and page scoping were checked locally. Eligibility is not a rich-result guarantee.
- Existing build warnings remain: missing local GA ID and deprecated Edge runtime in the social-image route. Existing lint warnings concern internal `window.location.assign` in the lead form and its mobile inspection copy. They are not introduced by the SEO changes.

Rollback: review only the SEO file list above. Restore the previous metadata/copy/video-loading behavior using a focused patch, preserving prior QA edits in `home-client.tsx`. If the new guide is later withdrawn after publication, evaluate inbound links/traffic and redirect it to a relevant replacement rather than silently deleting it. No database rollback is needed.

## 7. Measurement plan and 30/60/90-day roadmap

### First 30 days: release hygiene and a usable baseline

1. Review and approve a scoped release; record deployment URL, release timestamp, commit and any simultaneous pricing/product/campaign changes. Production release date is currently unset.
2. Validate canonical/image URLs, sitemap and noindex headers on the deployed site. Submit `/sitemap.xml` and inspect `/` and `/solar-guide` in Search Console. Do not request indexing of private reports or dashboards.
3. Export at least the preceding 28 days of Search Console clicks, impressions, CTR and average position by landing page/query/device/country; use the longest available history for seasonality. Keep branded and relevant non-branded queries separate. Preserve existing winners once data is available.
4. Audit the existing GA4 setup and privacy controls before activation. Reuse `address_selected`, `solar_data_loaded`, and `lead_submitted`; define whether a report was saved vs actually emailed. Only add a separate installer-consent conversion if it is deduplicated and contains no contact data. Do not count admin PDF downloads as homeowner acquisition.
5. Track weekly organic landing sessions, unique valid report requests, and separately opted-in qualified installer requests. Organic report conversion rate = unique report-converting organic sessions / eligible organic landing sessions, with both the denominator and attribution window documented.

### Days 31-60: improve proven opportunities

1. Compare matched 28-day windows and, where available, the prior year's same season. Segment mobile/desktop, brand/non-brand, relevant Arizona queries and landing pages. Note indexing lag, summer utility demand, paid traffic, outages and other releases before attributing changes to SEO.
2. Improve the homepage snippet or guide sections only where actual query impressions and behavior show an intent gap. Do not optimize for irrelevant impressions or a third-party score.
3. Measure field p75 LCP/INP/CLS through available Search Console/CrUX or approved privacy-preserving RUM. Lab samples below do not establish field improvement; low-traffic sites may lack CrUX coverage.
4. Review guide-to-calculator engagement, address-selection success, analysis success, report validation failures and opt-in rate. Use aggregate events; keep addresses, bills, report tokens and contact details out of analytics.

### Days 61-90: earn trust with original value

1. If demand is demonstrated, publish one permissioned, dated roof-model example with independently verified outcomes and clear limitations. Do not fabricate a testimonial or installer sign-off.
2. Extend the guide's utility or proposal-checklist sections only with current source review and product support; avoid mass city variants.
3. Consider legitimate mentions from homeowner education resources, local energy-efficiency organizations and verified partners after the owner confirms relationships. Offer a useful tool or methodology, not paid links. No outreach was performed.
4. Re-run regression and lab checks each release. Review source links and utility guidance quarterly; use actual editorial modification dates if lastmod is introduced later.

Success is more relevant organic visitors who successfully understand and request a useful report, with explicit installer consent when wanted. No target percentage lift is assigned without a reliable baseline.
